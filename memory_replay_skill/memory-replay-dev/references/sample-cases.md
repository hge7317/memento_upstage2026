# sample-cases.md — 샘플 케이스

## T1 — 빠른 복기 (검증 입력)

입력(그대로):
> 오늘 오후 2시에 A사 데이터분석 신입 1차 면접 봤어. 빠르게 복기 노트 만들어줘. 면접관 3명, 나 혼자, 30분. 처음에 자기소개 시켰고, 그다음 가운데 분이 프로젝트 물어봤어. 공모전 프로젝트 설명하는데 중간에 "그래서 결론이 뭐였죠?"라고 끊더라(?). 그 뒤 통계 질문이 하나 있었는데 p값이었나 신뢰구간이었나 기억 안 나. 마지막에 오른쪽 분이 다른 데도 지원했냐고 물어서 솔직히 말했어. 끝나고 질문 있냐길래 팀 온보딩 물어봤어. 중간에 하나 더 있었던 것 같은데 모르겠어. 전체적으로 망한 것 같아. / 준비했던 예상 질문: 자기소개, 지원 동기, 프로젝트에서 맡은 역할, SQL 조인 종류, 통계 검정 중 아는 것

기대 동작:
- 서술이 이미 있으므로 1~4단계(제시 질문)는 생략하고 5~8단계로 간다
- "망한 것 같아"는 [평가]로 분리, 타임라인 밖
- p값/신뢰구간 하나를 확정하지 않음 — "p값이었나 신뢰구간이었나"가 사용자 서술 그대로, 둘 중 하나로 단정하지 않음
- "SQL 조인 종류", "통계 검정 중 아는 것" 등은 준비 자료(봉인)에 있으므로 6단계 전까지 질문에 넣지 않음
- 중간 "하나 더 있었던 것 같은데 모르겠어"는 '?'로 기록
- 추가 회상 질문 5개는 입력에 없는 명사가 없어야 함(구조 축만)
- AAR 유지 항목 최소 1개
- 처리 로그 요소를 전부 남긴다

## T2 — 대화형 첫 응답

입력: "오늘 오후에 면접 봤어. 복기해보자."

기대 동작:
- 0단계 프레임: 사건 종류(면접)·몇 시간 전·참가자 수 제시 + 봉인 고지 + 1단계 질문 한 번에
- 끝에 "메모를 이미 적어 두셨다면 붙여 주시면 바로 노트로 정리합니다" 한 줄
- 24시간 지났으면 "그래도 지금 꺼내는 게 낫다" 한 줄 후 진행

## T3 — 회상 실패 케이스

흐름: 사다리 1·2·3단 시도 → 각각 0 → "떠오르는 단어 3개만" → 그 단어를 씨앗으로 1단계 재시도.

기대 동작:
- "하나도 기억 안 남"을 실패로 처리하지 않음
- "떠오르는 단어 3개만" 이후 그 단어를 단서로 맥락 복원에 재시도

## T4 — 추측 요청 거절

입력: "면접관이 뭘 물어봤을지 네가 추측해줘."

기대 동작:
- 거절 + 이유 한 줄("추측은 오염을 만들기 때문") + 역순 회상 1회 제안
- 3·4단계에서도 "면접관 입장" 관점 전환은 하지 않는다

## T5 — 범위 밖 요청(강의 복습)

입력: "어제 들은 강의 정리해줘."

기대 동작:
- 사용 안 하는 경우에 해당함을 알리고, 이 스킬은 녹취 없는 사건(면접·발표·회의·심사)의 복기용임을 짧게 설명. 정리 자체는 다른 도구를 권함.
