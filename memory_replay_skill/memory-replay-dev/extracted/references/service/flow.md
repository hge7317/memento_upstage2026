# 서비스 흐름과 원본 단계 매핑

이 문서는 SERVICE 모드 전용이다. 일반 대화의 원본 동작은 변경하지 않는다. 대표 memory-replay 스킬의 본문을 로딩한 상태에서 필요한 참조를 추가한다. 이 문서만으로 독립 회상 엔진을 만들지 않는다.

| 서비스 상태 | 담당 및 원본 연결 | 다음 상태 |
|---|---|---|
| SPLASH | 서비스 화면 | QUICK_MEMO |
| QUICK_MEMO | 텍스트·사진 입력, 원문 보존 | EXTRACT_CANDIDATES |
| EXTRACT_CANDIDATES | 대표 스킬의 확장 후보 추출 | USER_VERIFY |
| USER_VERIFY | 서비스 버튼으로 후보 확인 | JOB_POSTING_OPTIONAL |
| JOB_POSTING_OPTIONAL | 선택 URL 저장·배경 처리 | INTERVIEW_INITIAL_INFO |
| INTERVIEW_INITIAL_INFO | 원본 0단계 프레임을 서비스 폼으로 수집 | CONTEXT_REINSTATEMENT |
| CONTEXT_REINSTATEMENT | 원본 1단계 | FREE_RECALL |
| FREE_RECALL | 원본 2단계 | STRUCTURAL_CUE |
| STRUCTURAL_CUE | 원본 3단계, question_rules.md 적용 | REVERSE_RECALL |
| REVERSE_RECALL | 원본 4단계 | TIMELINE_REVIEW |
| TIMELINE_REVIEW | 원본 5단계 확신도 및 사용자 편집 | GENERATE_OUTPUT |
| GENERATE_OUTPUT | 원본 6~8단계, 갭·AAR·인출 카드·일정 | COMPLETE |
| COMPLETE | 서비스 결과 표시·보관 | 종료 |

## 완료 조건과 모드 예외

- 후보 추출은 추론 결과이지 사건의 진위 판정이 아니다. 모든 후보가 PENDING을 벗어나면 검증 완료다. 빈 후보나 모두 거절된 경우도 잡포스팅 선택과 기본 정보로 진행한다.
- 잡포스팅은 입력 또는 건너뛰기로 완료한다. 기본 정보는 회사·직무·일시·방식·면접 단계·면접관 수를 받되 모름·비공개를 허용한다. 이미 받은 필드는 다시 묻지 않는다.
- 원본의 ‘메모가 있으면 즉시 빠른 복기’와 첫 응답 프레임·첫 질문 묶음은 SERVICE에서는 적용하지 않는다. 검증된 기록을 초기 기억으로 쓰되 현재 회상 단계만 진행한다. 자유 서술에서 이미 쓴 내용을 전부 다시 요구하지 않고 더 떠오르는 내용을 받는다.
- 회상 질문 하나 원칙을 유지한다. 원본 요소 수+3 상한을 따르고 서비스 상한은 최대 12개다. 두 번 연속 모름이면 다음 미사용 단서 하나 또는 현재 내용으로 종료를 제안한다. 세 단서가 모두 소진되면 원본의 단어 씨앗 재시도 대신 종료 선택을 제공한다.
- 회상 중 사용자가 종료하면 TIMELINE_REVIEW로 이동을 제안한다. 검토 확인 전 결과를 확정하지 않는다.
- 준비자료는 검토 확정 후 명시적 대조 동의가 있을 때만 서비스가 제공한다. 동의 없으면 자료 대조를 생략하고 나머지 결과를 만든다. 원본의 재요청 시 조기 해제 예외는 SERVICE에서 적용하지 않는다.
- 결과는 기존 replay_note_template.md 순서를 사용한다. 근거 없는 ‘잘된 점 최소 1개’나 카드 5~8장을 억지로 채우지 않는다. 부족한 곳은 사용자 기입으로 남긴다. ‘준비했지만 안 나옴’은 ‘준비했지만 실제로 나왔다는 기억 없음’으로 표시한다.
- 서비스에서는 원본의 자동 파일 저장 대신 결과 콘텐츠를 반환하고 렌더러가 저장한다. 일정은 기존 schedule_calc.py 실행 결과를 사용한다. 도구 실패 시 원본의 수기 계산·전문 반환 대안을 유지한다.

상태 전이는 서버가 결정한다. 현재 상태, 검토 여부, 동의 정보가 누락되거나 잘못되면 연결 오류를 반환하고 단계를 추정하지 않는다.
