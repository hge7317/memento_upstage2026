## 1. 제품 개요

### 1.1 한 줄 정의

Memory Replay는 사건 직후 떠오르는 기억을 먼저 빠르게 보존하고, 사용자가 확인한 사실만을 바탕으로 AI가 단계적인 회상 질문을 제공하여 면접·분실·미팅 경험을 오염 없이 복기하도록 돕는 서비스다.

### 1.2 핵심 메시지

> 먼저 적고, 직접 확인하고, 안전하게 더 떠올립니다.

### 1.3 해결하려는 문제

1. 사건 직후의 기억은 빠르게 흐려지지만 정식 복기를 바로 시작하기는 부담스럽다.
2. 사용자가 급히 적은 메모에는 사실, 추측, 감정, 중복 표현이 섞여 있다.
3. 일반 생성형 AI는 사용자가 말하지 않은 세부 내용을 그럴듯하게 보충할 수 있다.
4. 빈 화면에서 한 번에 완전한 타임라인을 쓰기 어렵다.
5. 면접, 분실, 미팅은 필요한 객관 정보와 결과 형식이 서로 다르다.
6. 복기 결과를 다시 정리하거나 문서화하는 데 추가 시간이 든다.

### 1.4 제품 해법

- 정식 질문 전에 `빠른 메모`를 제공하여 사용자의 최초 기억을 보존한다.
- AI가 빠른 메모에서 핵심 기억 후보를 추출하되, 사용자의 O/X 확인 전에는 사실로 확정하지 않는다.
- 상황별 탭에 따라 Step 1의 객관 정보와 Step 2의 회상 질문을 다르게 구성한다.
- Step 2에는 인지면담 원칙에서 가져온 자유 회상, 맥락 복원, 다양한 구조 단서, 역순 확인을 적용한다.
- 모든 결과에 출처와 확신도를 남기고 Markdown 또는 PDF로 제공한다.

### 1.5 제품 원칙

1. **사용자 기억 우선:** AI는 기억을 생성하지 않고 사용자의 회상을 돕는다.
2. **빠른 기록 우선:** 완벽한 문장보다 사건 직후의 최초 기억을 먼저 보존한다.
3. **사용자 검증 우선:** AI 추출 내용은 O/X 확인 전까지 `후보`다.
4. **사실과 해석 분리:** 관찰·발언·행동과 감정·평가·추측을 분리한다.
5. **불확실성 보존:** 모르는 내용과 흐릿한 기억을 임의로 확정하지 않는다.
6. **비유도 질문:** 사용자가 언급하지 않은 구체 내용은 질문에 넣지 않는다.
7. **상황별 결과:** 같은 회상 엔진을 사용하되 입력 정보, 질문 초점, 산출물은 상황에 맞춘다.

## 2. 목표와 범위

### 2.1 사용자 목표

- 서비스 진입 후 1분 안에 기억나는 내용을 기록하기 시작할 수 있다.
- AI가 추출한 정보를 직접 확인·수정하여 잘못된 전제를 차단할 수 있다.
- 질문을 따라가며 처음 메모보다 더 구체적인 순서와 세부 내용을 떠올릴 수 있다.
- 기억, 추측, 감정을 구분한 결과물을 내려받을 수 있다.
- 면접 준비, 분실물 탐색, 미팅 후속 업무에 결과를 바로 활용할 수 있다.

### 2.2 서비스 목표

- `빠른 메모 → 사용자 검증 → 상황별 복기 → 결과`의 핵심 가치를 검증한다.
- 면접 중심 엔진을 분실물과 미팅으로 확장할 수 있는 공통 구조를 만든다.
- 질문 오염과 AI의 임의 확정을 제품 로직으로 방지한다.
- 모바일에서 10분 안에 전체 복기를 마칠 수 있게 한다.

### 2.3 MVP 범위

#### 포함

- 스플래시/시작 화면
- 상황 선택 탭: 면접 복기, 분실물 찾기, 미팅 복기
- 자유 형식 빠른 메모
- 핵심 기억 후보 자동 추출
- 후보별 O/X/모름 확인과 직접 수정
- Step 1 객관 정보 수집
- Step 2 인지면담 원칙 기반 대화형 회상
- 타임라인 편집과 확신도 표시
- 상황별 결과 화면
- Markdown 다운로드
- PDF 다운로드
- 세션 및 데이터 삭제

#### 제외

- 합격 가능성 예측
- 면접 답변의 정답·오답 판정
- 분실물의 실제 위치 보장 또는 실시간 위치 추적
- 타인을 범인으로 지목하거나 의도를 추정하는 기능
- 미팅 참석자의 감정·의도 분석
- 법적 진술 또는 수사 자료 생성
- 실시간 녹음·도청·자동 전사
- 회사·장소·사람에 대한 자동 웹 검색
- 타 사용자 데이터와의 비교

## 3. 목표 사용자와 사용 시점

### 3.1 면접 복기

- 대상: 취업 준비생, 이직 준비자, 프리랜서 지원자
- 사용 시점: 면접 종료 직후부터 24시간 이내
- 핵심 기대: 질문, 답변, 면접 진행 순서, 후속 준비 항목 복원

### 3.2 분실물 찾기

- 대상: 물건을 잃어버린 뒤 마지막 행동과 동선을 되짚고 싶은 사용자
- 사용 시점: 분실을 인지한 직후
- 핵심 기대: 마지막 확인 시점, 이동 동선, 접촉 행동, 확인할 장소와 다음 행동 정리

### 3.3 미팅 복기

- 대상: 녹취가 없거나 기록이 불완전한 업무 미팅 참석자
- 사용 시점: 미팅 종료 직후
- 핵심 기대: 논의 흐름, 결정사항, 미결사항, 담당자와 후속 행동 복원

## 4. 전체 서비스 플로우

```text
[앱/웹 실행]
      ↓
[스플래시·서비스 원칙 안내]
      ↓
[상황 탭 선택]
  ├─ 면접 복기
  ├─ 분실물 찾기
  └─ 미팅 복기
      ↓
[빠른 메모]
지금 떠오르는 내용을 순서·문장 형식과 관계없이 입력
      ↓
[AI 핵심 기억 후보 추출]
사실 후보 / 불확실 후보 / 평가·추측 후보로 분류
      ↓
[사용자 O/X 검증]
O 맞음 / X 아님·수정 / ? 모르겠음
      ↓
[Step 1: 상황별 객관 정보]
사건의 기본 프레임 수집
      ↓
[Step 2: AI 기억 복기]
맥락 복원 → 자유 회상 → 구조 단서 → 빈 구간 → 역순 확인
      ↓
[타임라인·확신도 검토]
사용자 수정·삭제·확정
      ↓
[상황별 결과 생성]
면접 노트 / 탐색 계획 / 미팅 복기록
      ↓
[Markdown 또는 PDF 다운로드]
      ↓
[세션 종료·데이터 삭제 선택]
```

### 4.1 화면 단위 플로우

| 화면 | 사용자 행동 | 시스템 동작 | 다음 조건 |
|---|---|---|---|
| 1. 스플래시 | 서비스 진입 | 로고와 핵심 메시지를 1~2초 표시 | 자동 이동 또는 건너뛰기 |
| 2. 상황 선택 | 탭 1개 선택 | 선택값을 세션에 저장 | 탭 선택 완료 |
| 3. 빠른 메모 | 텍스트 입력 후 `다음` | 원문을 그대로 보존하고 후보 추출 | 1자 이상 입력 또는 `기억이 안 남` |
| 4. O/X 검증 | 후보별 O/X/? 선택, 수정 | 검증된 사실 집합과 제외 항목 생성 | 모든 후보 처리 |
| 5. Step 1 | 객관 정보 입력 | 사건 프레임 구성 | 필수 필드 완료 |
| 6. Step 2 | 질문에 하나씩 답변 | 새 기억 추출·출처 기록·질문 안전 검사 | 완료 선택 또는 질문 상한 도달 |
| 7. 최종 검토 | 타임라인 수정, 확신도 선택 | 결과 데이터 확정 | `결과 만들기` 선택 |
| 8. 결과 | 확인·다운로드 | Markdown/PDF 생성 | 다운로드 또는 종료 |

### 4.2 뒤로 가기와 중도 종료

- 사용자는 결과 생성 전까지 이전 단계로 돌아갈 수 있다.
- 상황 탭을 변경하면 기존 입력이 새 상황과 맞지 않을 수 있음을 알리고, 빠른 메모 원문을 유지할지 선택하게 한다.
- 모든 복기 화면에 `현재 내용으로 결과 만들기`를 제공한다.
- 브라우저 이탈 시 입력 원문과 검증 상태를 임시 저장한다.
- 복구 기간과 자동 삭제 시점은 화면에 명시한다.

## 5. 빠른 메모

### 5.1 목적

빠른 메모는 정식 복기 전에 사용자의 최초 기억을 최대한 방해 없이 포착하는 단계다. 이 단계에서는 맞춤 질문, 평가, 요약 결과를 먼저 보여주지 않는다.

### 5.2 화면 구성

- 상황명과 짧은 안내
- 큰 텍스트 입력창
- 안내 문구: `순서가 뒤죽박죽이어도 괜찮습니다. 지금 떠오르는 말, 장면, 숫자, 장소를 그대로 적어 주세요.`
- `기억이 잘 안 남` 선택
- 입력 내용 삭제
- `다음` 버튼
- 선택 기능: 모바일 음성 입력

### 5.3 입력 규칙

- 최소 1자, 권장 최대 5,000자
- 줄바꿈, 단어 나열, 불완전한 문장 허용
- 맞춤법을 자동 교정하더라도 원문은 별도로 보존
- 감정과 평가가 포함되어도 입력을 막지 않음
- 서버 전송 전 사용자에게 민감정보 입력 주의 문구 제공

### 5.4 AI 추출 결과

AI는 원문을 다음 단위로 나눠 `기억 후보 카드`를 생성한다.

| 분류 | 의미 | 예시 |
|---|---|---|
| 사실 후보 | 사용자가 직접 기억한다고 쓴 사건·발언·행동 | `두 번째 질문 뒤에 포트폴리오를 열었다` |
| 불확실 후보 | 아마, 아마도, 정확하지 않음 등이 붙은 기억 | `아마 3시쯤 나왔던 것 같다` |
| 평가·추측 후보 | 잘했다, 화난 것 같다 등 사실과 분리할 표현 | `면접관이 내 답을 싫어한 것 같다` |

### 5.5 추출 원칙

- 한 카드에는 한 가지 확인 가능한 주장만 담는다.
- 원문에 없는 회사명, 장소명, 사람, 물건, 발언을 추가하지 않는다.
- 대명사가 불명확하면 임의로 해소하지 않고 원문 표현을 유지한다.
- 시간과 순서를 임의로 재배열하지 않는다.
- 요약 과정에서 불확실성 표현을 삭제하지 않는다.
- 각 카드에 원문 근거 구절을 연결한다.

### 5.6 O/X 검증

각 후보 카드에는 다음 선택을 제공한다.

- `O 맞아요`: 검증된 기억으로 채택
- `X 아니에요`: 사실 집합에서 제외
- `수정`: 사용자가 직접 고친 뒤 채택
- `? 모르겠어요`: 불확실한 기억으로 채택

O/X라는 핵심 개념은 유지하되, 거짓 양자택일을 피하기 위해 `수정`과 `?`를 함께 제공한다. `X`를 선택한 카드의 내용을 AI가 이후 질문의 전제로 사용해서는 안 된다.

### 5.7 검증 완료 조건

- 모든 카드가 O, X, 수정, ? 중 하나로 처리되어야 한다.
- 카드가 15개를 넘으면 묶음 검토와 `모두 확인 후 세부 수정` 기능을 제공한다.
- AI가 후보를 만들지 못해도 사용자의 원문은 그대로 Step 2에 전달한다.
- 검증 완료 후 `확인한 내용은 이후 질문의 출발점으로만 사용되며, AI가 사실을 추가하지 않습니다`를 표시한다.

## 6. 공통 복기 엔진

### 6.1 Step 1: 객관 정보 수집

Step 1은 회상 질문을 개인화하기 위한 사건의 프레임이다. 사용자의 기억 내용 자체를 평가하지 않는다.

공통 필드:

- 사건 날짜와 대략적인 시각
- 사건 종료 후 경과 시간
- 장소 유형(온라인/오프라인 포함)
- 참가자 수 또는 혼자였는지
- 사건 이름(사용자 지정, 선택)

입력 원칙:

- 정확한 날짜나 시각을 모르면 범위 또는 `모름` 허용
- 한 화면에 최대 3개 필드
- 상황별 필수 필드는 7~9절에서 정의

### 6.2 Step 2: AI 기억 복기

Step 2는 다음 순서로 진행한다.

1. **맥락 복원:** 사건 직전의 장소, 위치, 몸 상태, 주변 환경을 떠올리게 한다.
2. **자유 회상:** 처음부터 끝까지 기억나는 내용을 끊지 않고 입력하게 한다.
3. **구조 단서:** 시간 → 공간·감각 → 행동 순으로 단서를 제공한다.
4. **세부 명료화:** 사용자가 이미 언급한 요소에 대해서만 첫 문장, 다음 행동, 상대 반응 등을 묻는다.
5. **빈 구간 확인:** 내용으로 채워 넣지 않고 `시작과 끝 사이에 비어 있는 구간이 있습니다`처럼 구조만 알려준다.
6. **역순 확인:** 마지막 순간부터 거꾸로 되짚어 새 기억을 확인한다.
7. **완료 판단:** 사용자가 완료를 선택하거나 질문 상한에 도달하면 타임라인 검토로 이동한다.

### 6.3 질문 정책

- 한 화면·한 응답에는 회상 질문 하나만 표시한다.
- 열린 질문을 우선하고, 닫힌 질문은 사용자가 이미 말한 내용을 명료화할 때만 쓴다.
- 사용자가 먼저 언급하지 않은 구체 명사는 질문에 넣지 않는다.
- O/X 검증에서 X로 제외된 정보를 다시 질문에 넣지 않는다.
- `왜 그랬나요?`보다 `그 직전에 무엇이 있었나요?`처럼 관찰 가능한 순서를 우선한다.
- 답을 유도하는 선택지, 정답 암시, 다른 사용자의 사례를 보여주지 않는다.
- 상대의 시점에서 상상하게 하는 관점 전환은 사용하지 않는다.
- `모름`, `기억 안 남`, `넘기기`를 정상 응답으로 허용한다.
- 2회 연속 기억이 나지 않으면 단서 사다리 또는 현재 내용으로 종료를 제안한다.

### 6.4 질문 안전 검사

모든 AI 질문은 사용자에게 표시되기 전에 다음을 검사한다.

1. 미언급 구체 명사가 포함되었는가?
2. X 처리된 후보를 전제로 삼았는가?
3. 한 번에 둘 이상의 회상 질문을 했는가?
4. 사용자 기억을 평가하거나 정답으로 판정했는가?
5. 불확실한 기억을 확정형으로 바꾸었는가?
6. 상황별 금지 질문에 해당하는가?

검사 실패 시 질문을 보내지 않고 `그다음에 기억나는 것은 무엇인가요?`와 같은 구조 질문으로 교체한다.

### 6.5 확신도와 출처

각 기억 단위에는 다음 메타데이터를 저장한다.

- 확신도: `◎ 확실` / `△ 흐릿함` / `? 모름·복수 가능성`
- 출처: `빠른 메모` / `O/X 수정` / `자유 회상` / `구조 단서` / `역순 추가` / `사용자 최종 수정`
- 최초 입력 시각
- 사용자가 마지막으로 확인한 시각

확신도는 정확도의 보증이 아니라 사용자의 주관적 표시임을 결과에 안내한다.

## 7. 면접 복기 플로우

### 7.1 진입 문구

`면접 직후 떠오르는 질문, 답변, 장면을 먼저 적어 두세요. 순서가 정확하지 않아도 괜찮습니다.`

### 7.2 빠른 메모 예시

- `세 명이 있었음`
- `자기소개 다음에 프로젝트 질문`
- `내가 일정 얘기하다가 막힘`
- `마지막에 입사 가능일 질문`

예시는 입력 시작 전 도움말로만 제공하며, 실제 메모 작성 화면에 계속 노출하지 않는다. 예시 내용이 사용자의 기억에 섞이지 않게 접어서 제공한다.

### 7.3 Step 1 객관 정보

필수:

- 지원 회사명 또는 `공개하고 싶지 않음`
- 지원 직무/부서
- 면접 날짜와 대략적인 시각
- 면접 방식: 대면 / 화상 / 전화 / 기타
- 면접 단계: 서류 후 첫 면접 / 2차 / 최종 / 모름 / 직접 입력
- 면접관 수

선택:

- 예상 소요시간과 실제 체감 시간
- 면접 언어
- 다음 전형 또는 결과 예정일
- 준비자료 첨부 여부

회사명과 직무는 Step 1 이후 질문에 사용할 수 있지만, 사용자가 말하지 않은 회사 정보나 예상 질문을 외부에서 보충하지 않는다.

### 7.4 Step 2 질문 초점

1. 입장 또는 연결 직전 상황
2. 첫 인사와 시작 방식
3. 기억나는 질문의 순서
4. 각 질문에 대한 자신의 첫 답변과 이어진 설명
5. 사용자가 관찰한 후속 질문·말·행동
6. 막히거나 순서가 흐릿한 구간
7. 마지막 질문, 사용자 질문, 종료 장면
8. 마지막부터 거꾸로 확인

허용 질문 예:

- `처음 시작됐을 때 가장 먼저 기억나는 장면은 무엇인가요?`
- `방금 말한 질문에 답할 때 첫 문장은 무엇이었나요?`
- `그 답변 다음에 실제로 들리거나 보인 반응이 있었나요?`

금지 질문 예:

- `기술 면접에서 알고리즘 문제가 나왔죠?`
- `면접관이 답을 마음에 들어 하지 않았나요?`
- `그 답변은 틀린 것 같나요?`

### 7.5 면접 결과물

- 면접 기본 정보
- 시간순 질문·답변 타임라인
- 관찰된 후속 반응
- 확신도와 출처
- 분리된 감정·평가 문장
- 잘 유지할 점과 다음에 보완할 점(AAR)
- 준비자료가 있을 경우에만 준비 여부 대조
- 다음 면접용 인출 카드 5~8개
- 재연습 일정

## 8. 분실물 찾기 플로우

### 8.1 진입 문구

`물건을 마지막으로 봤던 순간부터 지금까지 떠오르는 장면과 행동을 먼저 적어 주세요.`

### 8.2 Step 1 객관 정보

필수:

- 잃어버린 물건의 사용자 표현
- 분실을 알아차린 시각
- 마지막으로 물건을 확실히 확인한 시각 또는 범위
- 마지막으로 확실히 확인한 장소
- 그 이후 이동한 장소 수 또는 `모름`

선택:

- 물건의 구별 특징
- 이동 수단
- 동행 인원
- 이미 확인한 장소와 조치
- 연락 가능한 시설/기관

### 8.3 Step 2 질문 초점

1. 마지막으로 물건을 확실히 본 장면
2. 그때 물건을 어디에 두거나 어떻게 들고 있었는지
3. 직후 한 행동
4. 이후 이동 동선과 각 구간의 전환점
5. 가방·주머니·책상 등 사용자가 먼저 언급한 보관 행동
6. 결제, 착석, 승하차, 옷 갈아입기 등 사용자가 먼저 언급한 접촉 장면
7. 분실을 처음 알아차린 장면
8. 현재까지 확인한 곳
9. 마지막 장면부터 역순 확인

안전 규칙:

- AI는 물건이 특정 장소에 있다고 단정하지 않는다.
- 사용자가 언급하지 않은 장소나 사람을 범인·원인으로 제시하지 않는다.
- 위험한 장소 재진입이나 타인 대면을 권하지 않는다.
- 카드, 신분증, 열쇠, 기기 등 민감 물품은 사용자가 입력한 유형에 따라 신고·잠금 등 일반 안전 조치를 별도 안내할 수 있다. 해당 안내는 `기억 결과`가 아니라 `권장 안전 조치`로 구분한다.
- 긴급하거나 범죄가 의심되는 상황은 공식 기관에 문의하도록 안내한다.

### 8.4 우선 확인 점수

시스템은 `가능성이 가장 높다`고 예측하지 않는다. 대신 사용자가 확인한 기억을 기준으로 다음 세 요소를 표시한다.

- 마지막 확실한 접촉과 가까운가
- 아직 확인하지 않은 곳인가
- 안전하고 현실적으로 확인 가능한가

이를 이용해 `확인 순서`를 제안하되, 추정 결과임을 표시한다.

### 8.5 분실물 결과물

- 물건 정보
- 마지막 확실한 확인 지점
- 시간순 이동·행동 타임라인
- 불확실하거나 비어 있는 구간
- 이미 확인한 장소
- 안전한 확인 순서 체크리스트
- 시설·기관에 전달할 수 있는 짧은 분실 설명문
- 확신도와 출처
- 즉시 필요한 안전 조치(해당 시)

## 9. 미팅 복기 플로우

### 9.1 진입 문구

`미팅에서 기억나는 논의, 결정, 숫자, 담당자, 다음 할 일을 순서와 관계없이 먼저 적어 주세요.`

### 9.2 Step 1 객관 정보

필수:

- 미팅명 또는 주제
- 날짜와 대략적인 시작 시각
- 진행 방식: 대면 / 화상 / 전화 / 기타
- 참석자 수
- 자신의 역할

선택:

- 알고 있는 참석자 이름·역할
- 예정된 안건
- 미팅 목적
- 종료 시각 또는 체감 시간
- 기존 안건·준비자료 첨부

### 9.3 Step 2 질문 초점

1. 시작 직전과 첫 발언
2. 논의된 주제의 실제 순서
3. 각 주제에서 사용자가 기억하는 발언
4. 명시적으로 합의된 결정
5. 제안되었지만 결정되지 않은 내용
6. 담당자·기한이 직접 언급된 후속 행동
7. 숫자·날짜·조건 중 흐릿한 부분
8. 종료 전 정리 발언과 마지막 장면
9. 마지막부터 역순 확인

분류 규칙:

| 분류 | 기준 |
|---|---|
| 결정 | 사용자가 실제 합의 표현을 기억함 |
| 제안 | 아이디어가 나왔지만 합의를 기억하지 못함 |
| 액션 아이템 | 행동, 담당자, 기한 중 최소 행동이 기억됨 |
| 미결 | 결론 또는 책임자를 기억하지 못함 |
| 개인 해석 | 참석자의 의도·감정에 대한 사용자의 추측 |

AI는 담당자나 마감일이 비어 있을 때 임의로 배정하지 않고 `[확인 필요]`로 남긴다.

### 9.4 미팅 결과물

- 미팅 기본 정보
- 논의 타임라인
- 결정사항 / 제안 / 미결사항 분리
- 액션 아이템 표: 할 일 / 담당자 / 기한 / 확신도 / 출처
- 확인이 필요한 숫자·날짜·표현
- 개인 해석·평가 분리
- 참석자에게 확인할 질문 목록
- Markdown/PDF 미팅 복기록

9. 회상 품질 로그

### 10.4 Markdown

## 11. 상태 모델

```text
SPLASH
→ SCENARIO_SELECT
→ QUICK_MEMO
→ EXTRACT_CANDIDATES
→ USER_VERIFY
→ OBJECTIVE_FRAME
→ CONTEXT_REINSTATEMENT
→ FREE_RECALL
→ STRUCTURAL_CUE
→ REVERSE_RECALL
→ TIMELINE_REVIEW
→ GENERATE_OUTPUT
→ COMPLETE
```

### 11.1 핵심 상태 규칙

- `EXTRACT_CANDIDATES` 결과는 아직 사실이 아니라 후보 데이터다.
- `USER_VERIFY` 완료 전에는 후보를 AI 질문의 확정 전제로 사용하지 않는다.
- X 처리된 후보는 이후 프롬프트 컨텍스트에서 제외하거나 `rejected`로 명확히 표시한다.
- 상황별 질문 모듈은 `OBJECTIVE_FRAME` 이후에만 활성화한다.
- 사용자가 언제든 `현재 내용으로 결과 만들기`를 누르면 `TIMELINE_REVIEW`로 이동한다.
- 결과 생성 이후 수정 시 새 버전을 만들고 기존 결과를 조용히 덮어쓰지 않는다.

### 11.2 권장 데이터 구조

```json
{
  "sessionId": "anonymous-id",
  "scenario": "INTERVIEW | LOST_ITEM | MEETING",
  "stage": "USER_VERIFY",
  "quickMemo": {
    "original": "사용자 원문",
    "createdAt": "ISO-8601"
  },
  "memoryItems": [
    {
      "id": "m-001",
      "claim": "사용자 기억 후보",
      "sourceQuote": "원문 근거",
      "category": "FACT | UNCERTAIN | EVALUATION",
      "verification": "CONFIRMED | REJECTED | EDITED | UNKNOWN",
      "confidence": "HIGH | MEDIUM | UNKNOWN",
      "source": "QUICK_MEMO"
    }
  ],
  "objectiveFrame": {},
  "timeline": [],
  "audit": {
    "injectionCheckPassed": true,
    "rejectedPremiseUsed": false
  }
}
```

## 13. UX 원칙과 주요 문구

### 13.1 스플래시

- 제목: `기억이 흐려지기 전에, 먼저 적어 두세요`
- 설명: `AI가 내용을 대신 만들지 않습니다. 당신이 확인한 기억을 바탕으로 더 잘 떠올리도록 질문합니다.`

### 13.2 상황 선택

- 제목: `어떤 일을 복기할까요?`
- 탭: `면접 복기` / `분실물 찾기` / `미팅 복기`
- 보조 문구: `상황에 따라 질문과 결과 형식이 달라집니다.`

### 13.3 빠른 메모

- 제목: `지금 바로 떠오르는 것부터`
- 설명: `정리하지 말고 그대로 적어 주세요. 단어만 써도 됩니다.`

### 13.4 O/X 검증

- 제목: `제가 이해한 내용이 맞나요?`
- 설명: `맞지 않는 내용은 반드시 X 또는 수정해 주세요. 확인 전에는 사실로 사용하지 않습니다.`

### 13.5 Step 2

- 제목: `기억을 차근차근 되짚어 볼게요`
- 상시 동작: `모름` / `넘기기` / `현재 내용으로 끝내기`

### 13.6 금지 UX

- 기억이 안 난다는 이유로 경고, 실패, 낮은 점수를 표시하지 않는다.
- 질문 수를 게임 점수처럼 표현하지 않는다.
- AI 후보를 체크된 정답 상태로 미리 보여주지 않는다.
- 확신도를 정확도 점수처럼 시각화하지 않는다.
- 분실물 위치나 면접 결과를 확률로 예측하지 않는다.

## 15. 개인정보·보안·안전

- 최소 수집을 기본으로 하고 로그인 없이 사용할 수 있게 한다.
- 원문, 추출 후보, 답변, 결과를 세션별로 격리한다.
- 모델 요청과 오류 로그에 불필요한 식별정보를 남기지 않는다.
- 원문과 결과의 자동 삭제 시간을 명시한다.
- 사용자 삭제 시 원문, 중간 추출물, 파일, 결과를 함께 삭제한다.
- 회사명, 사람 이름, 연락처, 카드·신분증 정보 입력에 주의 문구를 제공한다.
- 사용자가 X 처리하거나 결과에서 제외한 내용은 다운로드 결과에 포함하지 않는다.
- 회상 데이터는 별도 동의 없이 모델 학습, 광고, 사용자 프로필 구축에 사용하지 않는다.
- 서비스는 기억 정확도, 분실물 회수, 면접 합격, 업무 합의를 보장하지 않는다.
- 범죄, 법적 분쟁, 의료·정신건강 판단을 위한 전문 도구로 제시하지 않는다.

## 16. 연구 근거와 적용 한계

### 16.1 적용할 원칙

- **자유 회상 우선:** 사용자가 자신의 방식으로 충분히 말하게 한 뒤 명료화한다.
- **맥락 복원:** 사건 당시의 물리적·개인적 맥락을 떠올리게 한다.
- **다양한 인출 경로:** 같은 내용을 반복 강요하지 않고 시간, 공간·감각, 행동 단서를 달리한다.
- **열린 질문:** 구체적 닫힌 질문보다 열린 질문을 우선한다.
- **비유도 질문:** 질문자의 추정이나 기대를 질문에 넣지 않는다.
- **반복 회상 기회:** 한 번에 모든 기억이 나오지 않을 수 있으므로 역순 또는 후속 회상 기회를 제공한다.

### 16.2 근거 요약

- 인지면담에 대한 메타분석은 일반적인 통제 면담보다 정확하게 회상된 세부 정보가 증가하는 전반적 효과를 보고했다. 다만 일부 조건에서는 오류 정보도 함께 늘 수 있어, 본 제품은 ‘더 많이 떠올림’을 ‘정확성 보장’으로 표현하지 않는다.
- 실제 피해자·목격자를 대상으로 한 초기 현장 연구에서도 훈련받은 면담자가 더 많은 정보를 얻은 결과가 보고되었다. 이 결과는 수사 맥락의 연구이므로 일상적 면접·미팅·분실 상황에 동일한 효과가 난다고 단정하지 않는다.
- 반복 인지면담 연구에서는 두 번째 회상 기회에 새로운 정보가 추가될 수 있음을 보여준다. 따라서 역순 확인과 선택적 D+1 회상을 제품에 반영한다.
- 영국 법무부의 공식 면담 지침도 개인의 기억 구조에 맞춘 질문, 열린 질문 우선, 유도 질문 회피를 강조한다.

### 16.3 제품 표현 원칙

사용 가능 표현:

- `인지면담 연구에서 영감을 받은 회상 절차`
- `기억을 더 체계적으로 꺼내도록 돕습니다`
- `유도 질문과 AI의 임의 보충을 줄이도록 설계했습니다`

금지 표현:

- `기억을 정확하게 복원합니다`
- `과학적으로 진실을 판별합니다`
- `경찰 심문 기법으로 거짓말을 잡습니다`
- `분실물 위치를 찾아냅니다`

## 18. QA 수용 시나리오

### 18.1 공통

1. 단어만 나열한 빠른 메모에서도 후보 카드가 생성된다.
2. `아마`가 포함된 문장은 불확실 후보로 유지된다.
3. AI가 원문에 없는 고유명사를 후보에 추가하지 않는다.
4. X 처리된 후보가 이후 질문과 결과에 나타나지 않는다.
5. 수정한 후보는 수정 원문과 출처를 유지한다.
6. 모든 후보를 ?로 처리해도 복기를 계속할 수 있다.
7. 질문은 항상 하나씩 표시된다.
8. `모름`을 선택해도 오류나 실패로 표시되지 않는다.
9. 중도 종료해도 현재까지의 결과를 받을 수 있다.
10. Markdown과 PDF 내용이 화면 결과와 일치한다.

### 18.2 면접

1. 회사명을 비공개로 두어도 진행 가능하다.
2. 사용자가 기술 질문을 말하지 않았다면 AI가 기술 질문을 제시하지 않는다.
3. `망한 것 같다`는 평가 영역으로 분리된다.
4. 질문·답변·관찰된 반응이 서로 다른 필드에 저장된다.
5. 준비자료가 없다면 갭 분석을 억지로 생성하지 않는다.

### 18.3 분실물

1. 마지막 확실한 확인과 추정 구간이 분리된다.
2. AI가 특정 장소를 실제 위치로 단정하지 않는다.
3. 사용자가 언급하지 않은 사람을 의심하게 만들지 않는다.
4. 민감 물품에는 기억 결과와 분리된 안전 조치가 표시된다.
5. 확인 순서는 안전성·미확인 여부·마지막 접촉 근접성을 근거로 보여준다.

### 18.4 미팅

1. 결정과 제안이 분리된다.
2. 담당자·기한이 기억나지 않으면 `[확인 필요]`로 남는다.
3. 숫자와 날짜의 불확실성이 보존된다.
4. 참석자의 의도 추정은 개인 해석으로 분리된다.
5. 액션 아이템마다 출처와 확신도가 표시된다.

## 21. 미결정 사항

아래 항목은 출시 전에 제품 책임자가 확정한다.

1. 상황 탭을 첫 출시부터 3개 모두 공개할지, 면접만 정식·나머지는 베타로 표시할지
2. 스플래시를 매 방문마다 표시할지, 최초 방문에만 표시할지
3. 빠른 메모 음성 입력을 MVP에 포함할지
4. O/X 검증 카드가 많을 때 최대 노출 수와 묶음 검토 방식
5. 준비자료 첨부와 봉인 해제 기능을 v0.2 MVP에 유지할지
6. PDF를 서버에서 만들지 브라우저에서 만들지
7. 익명 세션 자동 삭제 기간과 복구 코드 유효시간
8. 분실물 안전 안내의 국가·지역별 공식 연락처 제공 범위

권장안은 `면접 정식 + 분실물/미팅 베타`, `최초 방문 스플래시`, `음성 입력은 Should Have`, `후보 20개 초과 시 묶음 검토`다.

## 22. 기존 v0.1 대비 변경 사항

| 항목 | v0.1 | v0.2 |
|---|---|---|
| 진입 | 사건 정보 입력 | 스플래시 → 상황 탭 |
| 빠른 기능 | 메모가 있으면 즉시 결과 생성 | 모든 복기의 첫 기억 포착 단계 |
| AI 추출 | 바로 타임라인 구성 | 후보 추출 후 사용자 검증 필수 |
| 사용자 검증 | 결과 단계 확신도 중심 | 복기 시작 전 O/X/?/수정 |
| 상황 범위 | 면접 중심, 발표·회의 확장 | 면접·분실물·미팅 명시 |
| 질문 구조 | 공통 0~8단계 | 공통 엔진 + 상황별 Step 1·2 |
| 결과 | 복기노트·AAR·카드 | 상황별 전용 결과 + Markdown/PDF |
| 상태 모델 | FRAME부터 시작 | QUICK_MEMO·USER_VERIFY 추가 |

### 구현 영향

현재 `memory-replay` 스킬에서 `첫 입력에 사건 서술이 있으면 1~4단계를 생략하고 바로 결과를 생성`하는 빠른 복기 규칙은 이 PRD와 충돌한다. 구현 시 다음처럼 변경해야 한다.

- `빠른 복기`라는 이름을 `빠른 메모`로 변경
- 첫 메모를 결과 입력이 아니라 `후보 추출 대상`으로 처리
- `USER_VERIFY` 완료 전 Step 2와 결과 생성을 차단
- 면접/분실물/미팅별 Step 1 스키마와 Step 2 질문 초점 추가
- 기존 확신도 단계는 유지하되 O/X 검증과 목적을 구분

## 23. 최종 제품 정의

Memory Replay의 핵심은 AI가 사용자의 사건을 요약하는 것이 아니라, 사용자가 기억을 잃거나 외부 정보에 영향을 받기 전에 다음 네 가지를 순서대로 수행하게 하는 데 있다.

1. **기억 포착:** 빠른 메모로 최초 기억을 보존한다.
2. **전제 검증:** AI가 이해한 내용을 사용자가 O/X/?/수정으로 확인한다.
3. **추가 회상:** 확인된 정보만을 바탕으로 비유도 질문을 제공한다.
4. **행동 가능한 기록:** 상황별 결과를 Markdown 또는 PDF로 만든다.

따라서 Memory Replay는 ‘답을 만들어 주는 AI’가 아니라 ‘사용자가 자신의 기억을 안전하게 꺼내고 확인하도록 돕는 회상 워크플로’다.
