# 프롬프트: 전 화면 좌측 상단 서비스 로고 클릭 → 홈(스플래시) 이동

## 작업 목표

Memory Replay 프론트엔드의 **모든 화면 좌측 상단**에 서비스 로고(브랜드 아이콘 + "Memory Replay" 텍스트)를 표시하고, 로고 클릭 시 **홈 화면(splash 단계)으로 이동**하게 만든다.

## 현재 상태

- `frontend/src/App.jsx` — 메인 상태 머신. `stage` 값에 따라 각 단계 컴포넌트를 `<main>` 안에 조건부 렌더링.
- `frontend/src/components/Splash.jsx` — 스플래시 화면. `.brand` div 안에 `.brand-icon`(`M`) + `.brand-name`(`Memory Replay`) 존재 → 이것이 서비스 로고.
- 현재 로고/헤더는 **어느 화면에도 공유되지 않음**. 스플래시에만 존재.
- "홈" = `stage === "splash"`.

## 구현 방향 (하나만 선택·준수)

**A안 — App.jsx에 공유 헤더 래퍼를 추가한다 (권장).**

`<main>` 내부, 각 단계 렌더링 위에 **공통 헤더**를 하나 둔다. 헤더는 모든 단계에서 표시되며, 로고 클릭 시 `setStage("splash")`를 호출한다.

- 헤더 컴포넌트는 인라인으로 정의하거나 별도 파일로 빼도 된다. 별도 파일로 뺄 경우 `frontend/src/components/Header.jsx`에 작성하고 App.jsx에서 import.
- 스플래시 화면 자체에 헤더를 겹쳐서 표시하지 않는 것이 자연스럽다. 스플래시 단계에서는 헤더를 숨기거나 표시하지 않는 조건을 넣는다.
- 로고의 시각 표현은 Splash.jsx의 기존 `.brand` 스타일(아이콘 + 이름)을 재사용한다. CSS를 추가/수정할 수 있다.

**B안은 사용하지 않는다** — 각 컴포넌트에 로고를 개별 추가하는 방식은 중복·불일치 위험이 크므로 허용하지 않는다.

## 범위

### 하는 것
- 모든 화면에 공통으로 표시되는 좌측 상단 로고 영역 추가
- 로고 클릭 → `setStage("splash")` 호출 → 홈 이동
- 기존 단계 전환 로직(`next`, `back`, `goTo` 등)은 건드리지 않는다
- Splash.jsx의 기존 `.brand` 스타일을 최대한 재사용

### 하지 않는 것
- 개별 단계 컴포넌트(Splash, QuickMemo, UserVerify 등) 내부 수정 ❌ (App.jsx에서만 작업)
- 새로운 외부 라이브러리 추가 ❌
- 상태 관리 방식 변경 (useState, useStage 훅 등 그대로) ❌
- "홈"의 정의 변경 — 홈은 여전히 `stage === "splash"` ❌
- 스플래시 화면에 로고를 이중으로 표시하지 않는다 (헤더가 스플래시에서 숨겨져야 함) ❌

## 완료 기준 (체크리스트 — 모두 통과해야 완료)

1. [ ] 앱이 정상적으로 빌드된다 (`cd frontend && npm run build` 성공, 또는 기존 방식).
2. [ ] splash를 제외한 모든 단계에서 좌측 상단에 서비스 로고(아이콘 + "Memory Replay")가 보인다.
3. [ ] splash 단계에서는 헤더/로고가 표시되지 않는다 (또는 표시되어도 홈 이동 의미가 없으므로 시각적으로 겹치지 않는다).
4. [ ] 어느 단계에서든 로고 클릭 → splash 단계로 전환된다 (홈 이동).
5. [ ] 로고 클릭 후 다시 각 단계로 이동하는 기존 흐름(예: "복기 시작하기" 버튼 등)이 정상적으로 동작한다.
6. [ ] 콘솔 에러 없이 동작한다.
7. [ ] 기존 컴포넌트 파일(Splash.jsx, QuickMemo.jsx 등)은 수정되지 않았다 — 변경은 App.jsx(및 추가한 Header.jsx)에 국한된다.

### 처리 완료 목록 (이 목록의 항목은 재방문하지 않는다)

- W-logo-2: App.jsx에 헤더 렌더링 추가 + setStage("splash") 연결
- W-logo-3: 스플래시에서 헤더 숨김 처리
- W-logo-4: CSS 조정 (필요 시)

### 범위 바깥 (명시적 배제)

- 상태 관리 리팩토링
- 다른 단계 간 전환 로직 수정
- 개별 컴포넌트 내부 로고 추가
- 새 의존성 추가
- 백엔드/모의 API 변경

### 조기 완료 방지

- "로고를 추가했다"에서 멈추지 말고 **모든 단계**에서 보이는지 확인한다. stage가 여러 개인 앱이므로 하나라도 누락되면 미완료.
- "클릭된다"에서 멈추지 말고 **클릭 후** splash 화면이 정상적으로 렌더링되는지 확인한다.
- 빌드 성공만 확인하지 말고 **실제 동작**(클릭→전환→재이동)을 확인한다.
- 완료 기준 7개 항목을 하나씩 체크하면서 진행한다. 체크되지 않은 항목이 있으면 완료로 간주하지 않는다.

## 작업 순서

1. Splash.jsx의 `.brand` markup과 관련 CSS 클래스(`.brand`, `.brand-icon`, `.brand-name`)를 확인하여 로고 표현 방식을 파악한다.
2. App.jsx에서 `<main>` 내부의 stage별 렌더링 구조를 확인한다.
3. 공유 헤더 컴포넌트를 추가한다 (A안). 헤더는 (a) splash 단계가 아닐 때만 렌더링, (b) 로고 클릭 시 `setStage("splash")`.
4. 기존 `.brand` 스타일을 재사용하거나, 필요한 CSS를 App.css에 추가한다.
5. 빌드를 실행하고 완료 기준 1~7을 확인한다.
6. 완료되지 않은 항목이 있으면 해당 항목만 보완한다. 모든 항목이 체크되면 종료.
