# 메멘토 — 제출용 PRD 요약

**서비스명:** 메멘토  
**스킬 명:** Memory Replay   
**상태:** 제출용 요약

메멘토는 종료된 면접을 복기하는 데 특화된 서비스다. 면접 직후에 떠오르는 질문, 답변, 장면을 자유롭게 메모로 남기면, AI가 이를 사실 후보와 평가·추측으로 나누어 사용자가 하나씩 검증할 수 있게 돕는다. 핵심은 AI가 기억을 대신 채우거나 추측하지 않는다는 점이다.

---

## 1. 제품과 사용자 경험

### 1-1. 문제 및 핵심 타깃

면접이 끝나면 질문과 답변이 흐려지고, 실제로 있었던 일과 그렇게 느껴진 일, 지어낸 내용이 섞이기도 한다. 메멘토의 핵심 타깃은 **취업준비생**이다. 면접 직후에 빠르게 기억을 남기고, AI가 상황별로 질문 하나씩을 던지며 추가 회상을 돕는 방식으로, 기억을 정리된 기록으로 남길 수 있게 한다.

### 1-2. 핵심 가치와 차별점

- **AI가 기억을 대신 채우지 않는다.** 빠른 메모를 사실 후보와 평가·추측으로 나누어 제시할 뿐, 진위를 판정하거나 빈 기억을 추측으로 채우지 않는다.
- **사용자 검증 중심:** 각 후보는 O/X/?/수정/‘이런 내용 없음’으로 확인한다. 거절한 후보는 이후 질문·요약·결과에서 사용하지 않는다.
- **불확실성 보존:** ‘아마’, ‘정확하지 않음’, ‘모름’을 확정형으로 바꾸지 않고 그대로 남긴다.
- **사실과 평가 분리:** 관찰·발언·행동과 사용자의 평가·감정·추측을 별도 항목으로 보존한다.

### 1-3. 주요 사용자 흐름

1. **SPLASH** — 서비스 진입
2. **QUICK_MEMO** — 면접 직후 빠른 메모 입력, 텍스트 또는 사진 업로드
3. **EXTRACT_CANDIDATES** — 메모에서 사실·평가·불확실 후보 추출, 사진·Document Parse 결과도 입력 가능
4. **USER_VERIFY** — 후보별로 O/X/?/수정/‘이런 내용 없음’ 선택
5. **JOB_POSTING_OPTIONAL** — 선택적으로 잡포스팅 URL 입력 (배경 자료)
6. **INTERVIEW_INITIAL_INFO** — 면접 기본 정보 수집 (회사·직무·일시·방식·단계·면접관 수 등)
7. **회상 단계** — 사건 직전 맥락 → 자유 서술 → 시간·공간·감각·행동 단서로 확인 → 마지막 순간부터 역순 회상
8. **TIMELINE_REVIEW** — 기억·평가·불확실성 구조 확인 및 수정
9. **GENERATE_OUTPUT → COMPLETE** — 면접 복기 결과 생성, 기록 아카이브 보관

빠른 메모 이후 상황 선택 단계는 없으며, 면접 기본 정보는 사용자 검증과 선택적 잡포스팅 URL 입력 이후에 받는다.

### 1-4. 흐름도

```
빠른 메모(텍스트/사진)
→ 후보 추출(사실·평가·불확실)
→ 사용자 검증(O / X / ? / 수정 / 이런 내용 없음)
→ 선택적 잡포스팅 URL 입력
→ 면접 기본 정보 수집
→ 추가 회상(맥락 → 자유 서술 → 단서 확인 → 역순)
→ 타임라인 검토
→ 복기 결과 생성
```

## 2. 요구사항과 스킬 활용

### 2-1. MVP 필수 기능

- **빠른 메모 입력:** 면접 직후 텍스트 메모 또는 사진 업로드
- **후보 추출 및 분류:** 사실(FACT), 불확실(UNCERTAIN), 평가(EVALUATION)로 나누어 제시
- **사용자 검증:** O/X/?/수정/‘이런 내용 없음’ 선택지 제공
  - O → CONFIRMED
  - X → REJECTED, 해당 후보에 삭제·수정 버튼 노출
  - ? → UNKNOWN
  - 수정 후 확인 → EDITED
  - ‘이런 내용 없음’ → REJECTED
- **기억 복기 질문:** 한 번에 질문 하나씩, 열린 질문 우선, 유도 질문 회피
- **면접 기본 정보 수집:** 회사·직무·일시·방식·단계·면접관 수 등
- **타임라인 검토:** 시간순 또는 순서 미상 타임라인, 평가·추측 분리, 불확실 구간 표시
- **복기 결과 생성:** 면접 복기 템플릿 기반 Markdown 문서, 상단에 ‘기억 구조화 기록이며 녹취나 사실 확인이 아님’ 고지
- **기록 관리:** 아카이브 보관, 삭제 시 휴지통 30일 보존, 기간 내 복구 가능

### 2-2. 예선 스킬 매핑 및 서비스 확장.

이 요약본은 제출용 문서이며, 예선 스킬 원본과의 차이, 실제 호출 방식, 수정·확장 범위는 확인할 수 없는 부분이 있다. 따라서 아래처럼 구분한다.

- **서비스 레이어에서 정의된 역할과 흐름:** 빠른 메모 입력, 후보 추출·검증, 면접 기본 정보, 잡포스팅 URL, 회상 질문, 타임라인 검토, 결과 생성, 기록 관리 등은 본 PRD에 정의된 서비스 요구사항이다.
- **예선 원본 스킬과의 실제 대응 관계:** 예선 당선 스킬이 어떤 기능 단위로 구성되었는지, 어느 부분이 그대로 호출되고 어느 부분이 서비스 레이어에서 수정·확장되었는지는 여기서는 확정하지 않는다.

### 2-3. 핵심 기술 구성

- **회상 진행 엔진:** 빠른 메모에서 기억 후보를 추출하고, 사용자 검증 상태를 해석하며, 비유도 회상 질문을 생성하고, 기억 항목·타임라인을 구조화하고, 상황별 결과 콘텐츠를 만든다.
- **입력 범위:** 빠른 메모 텍스트, 사진, Document Parse 결과 텍스트를 후보 추출 및 회상 질문 생성 입력으로 사용할 수 있다. 단, 사진은 기억 후보를 보강하는 용도로만 사용하고, AI가 사진을 통해 새로운 사건 사실을 만들어 넣지 않는다.
- **자료 구분:**
  - **빠른 메모용 사진·Document Parse 결과:** 후보 추출·회상 질문 생성 입력 가능, 사용자 검증 필요
  - **봉인 대상 준비자료:** TIMELINE_REVIEW 확정 및 사용자 대조 동의 후에만 열람, 대조 결과는 별도 섹션
  - **잡포스팅 URL:** 선택적 배경 자료, 실제 면접 기억의 근거로 취급하지 않음
- **출력 계약:** 단계별 응답을 구조화된 JSON으로 반환하며, 자연스러운 대화 모드에서도 같은 의미 구조를 유지한다.

### 2-4. 규칙 요약

- 추측 금지: 사용자가 제공하지 않은 사건 내용, 고유명사, 사람, 장소, 발언, 원인, 감정을 만들지 않는다.
- 검증 전 후보는 사실이 아니다.
- REJECTED와 ‘이런 내용 없음’은 이후 질문·요약·결과의 전제로 사용하지 않는다.
- ‘아마’, ‘정확하지 않음’, ‘모름’은 확정형으로 바꾸지 않는다.
- 관찰·발언·행동과 평가·감정·추측을 분리한다.
- 결과는 녹취, 객관적 사실 확인, 정확한 기억 복원으로 표현하지 않는다.
- 외부 자료를 실제 면접 기억으로 보충하지 않는다.

### 2-5. 성공 지표와 검증 기준

- 사용자가 빠른 메모를 제출하면 후보 추출 후 반드시 사용자 검증 단계를 거친다.
- O/X/?/수정/‘이런 내용 없음’ 선택지는 각각 CONFIRMED/REJECTED/UNKNOWN/EDITED/REJECTED로 대응한다.
- X 선택 시 해당 후보에 삭제·수정 버튼만 노출하고, 수정은 해당 후보 자체만 대상으로 한다.
- 모든 후보가 처리되기 전에는 JOB_POSTING_OPTIONAL 단계로 넘어가지 않는다.
- 잡포스팅 URL은 입력하지 않아도 진행이 가능하며, 입력한 경우에도 공고 내용을 실제 면접 사건으로 전제하지 않는다.
- 면접 기본 정보는 회상 맥락과 결과 생성의 프레임이며 실제 사건 내용의 정답지가 아니다.
- 삭제 시 기록은 아카이브에서 제거되고 휴지통으로 이동하며, 30일 보존 기간 중 복구하면 아카이브에 다시 표시된다. 30일 이후 자동 복구하지 않으며, 만료 후 처리는 추후 확정한다.
- 결과 문서 상단에는 ‘기억을 구조화한 기록이며 녹취나 객관적 사실 확인 결과가 아님’을 명시한다.
